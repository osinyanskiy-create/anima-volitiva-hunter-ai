# Платформа аудиту діалогів «Anima Volitiva»

Интеллектуальная система контроля качества, автоматического аудита разговоров торговых агентов и управления корпоративной базой знаний на основе искусственного интеллекта (Gemini 2.5).

---

## 🎯 1. Цель проекта
Автоматизация контроля стандартов продаж и сервиса торговых агентов компании «Anima Volitiva». Система анализирует текстовые расшифровки (или аудиозаписи) визитов на торговые точки, оценивает соблюдение 6 ключевых критериев, рассчитывает объективный балл комплаенса, находит пробелы в знаниях (Gap Analysis) и помогает супервайзеру точечно улучшать навыки команды.

---

## 📋 2. Требования к системе
- **Многоролевой интерфейс**: поддержка разделения на Торгового агента (для внесения данных о визитах) и Супервайзера (для глубокой аналитики).
- **Оценка по 6 жестким критериям** с общим весом в 100 баллов:
  1. **Водоподготовка и защита оборудования** (вес 20): замер воды TDS-метром (норма до 180 ppm), инструктаж по защите от морозов.
  2. **Дегустация и правило первой чашки** (вес 15): приготовление первой чашки себе, презентация купажа (9 грамм на порцию).
  3. **Финансовая дисциплина и ингредиенты** (вес 20): оплата по факту (без дебиторки), запрет сторонних ингредиентов.
  4. **Условия субаренды и 2-месячный тест** (вес 20): предупреждение об аудите через 8 недель (ориентир 4 кг) и 3 сценариях при низких продажах.
  5. **Работа с возражениями ЛПР** (вес 15): согласие, фокус на конечного покупателя, предложение тест-драйва.
  6. **Дополнительные продажи (Give to hand)** (вес 10): активное предложение кофе в пачках (120 грн) и чая (75 грн), передача товара в руки ЛПР.
- **Интеллектуальное исключение (Контекст роли)**: если агент общается только с продавцом (а не с ЛПР), критерии по финансам, субаренде и воде не должны штрафоваться (автоматически помечаются как выполненные).
- **Живой Gap-анализ**: автоматическое сравнение системных ошибок агентов в последних 5 аудитах с активными регламентами базы знаний для выявления пробелов и генерации предложений по созданию новых правил.
- **Интерактивное управление базой знаний**: добавление, удаление и мгновенное включение/выключение регламентов для ИИ-оценщика.

## 🛠️ 3. Принятые решения и Архитектура
- **Технологический стек**: full-stack приложение на базе **React 18+ (Vite)** на клиенте и **Express** на сервере.
- **База данных**: плоское файловое хранилище на диске (`db-store.json`) для мгновенного сохранения состояния между перезапусками сервера.
- **ИИ-интеграция**: использование современного SDK `@google/genai` с моделью `gemini-2.5-flash` для надежного, быстрого и экономичного структурированного разбора аудио/текстов.
- **Детерминированный расчет баллов**: ИИ отвечает за качественную оценку («completed», «partial», «failed») и текстовое обоснование со ссылками на регламенты, а расчет финального балла комплаенса (0–100) строго контролируется бэкенд-сервером на основе прописанных весов во избежание галлюцинаций ИИ.
- **Ультра-надежный парсинг**: внедрен защищенный парсинг JSON-ответов от Gemini, очищающий markdown-теги, пробельные символы и возможный лишний текст.
- **Безопасность**: все чувствительные переменные (включая `GEMINI_API_KEY`) вынесены в файл `.env`, который надёжно скрыт от системы контроля версий через `.gitignore`.

## 🏃 4. Как запускать и проверять результат

### Настройка окружения
1. Создайте в корневой директории файл `.env` на основе шаблона `.env.example`:
   ```env
   GEMINI_API_KEY="ВАШ_КЛЮЧ_GEMINI"
   PORT=3000
   ```

### Локальный запуск
1. Установите зависимости (если необходимо):
   ```bash
   npm install
   ```
2. Запустите dev-сервер:
   ```bash
   npm run dev
   ```
3. Откройте приложение в браузере по адресу `http://localhost:3000`.

### Сборка и проверка качества
- **Проверка типов TypeScript и linter**:
  ```bash
  npm run lint
  ```
- **Продакшн сборка**:
  ```bash
  npm run build
  ```
- **Запуск продакшн сборки**:
  ```bash
  npm run start
  ```

## ❓ 6. Открытые вопросы и дальнейшее развитие
1. **Интеграция аудио**: на данный момент поддерживается передача текстовых диалогов и симуляция аудио-контента. В дальнейшем планируется интеграция полноценной облачной телефонии или Telegram-ботов для автоматической отправки реальных записей звонков/визитов на сервер.
2. **Масштабируемость БД**: при росте количества точек и ежедневных аудитов файловая база данных `db-store.json` потребует миграции на более производительное решение, например, Firestore или PostgreSQL.
3. **Расширение критериев**: возможность кастомизации списка критериев оценки и их весов прямо из административного веб-интерфейса супервайзера без изменения исходного кода.
